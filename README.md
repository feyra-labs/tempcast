<h1 align="center">МАЯК</h1>

<p align="center"><b>Вероятностный прогноз температуры воздуха на 168 часов по одной метеостанции,
с потоковым рантаймом для слабого устройства.</b></p>

МАЯК получает почасовую историю одной точки (температура, давление, влажность и маска
пропусков), её координаты и высоту и выдаёт 7 квантилей (5, 10, 25, 50, 75, 90 и 95 %)
на каждый из 168 часов вперёд. Обучение идёт только на реанализе ERA5; наблюдения реальной
сети GHCNh служат внешним тестом. На устройстве модель работает в рантайме на Rust с ONNX
Runtime: один бинарник, фиксированная память, состояние переживает перезапуск.

**Ограничения проекта.**

- Температура — целые градусы Цельсия везде: в данных, кэше, истории, цели обучения и оценки,
  рантайме и состоянии устройства. Влажность — целые проценты, давление — десятые гПа.
  Значения округляются при поступлении. Что прибор присылает именно °C, обеспечивает
  владелец прибора; единицы не проверяются.
- Датчик отчитывается раз в час. Пропуски отдельных часов и разрывы допустимы; регулярный
  шаг в несколько часов вне области проекта.
- Время — UTC, момент наблюдения лежит на целом часе. Нужны координаты и высота точки: без
  них не определены солнечная геометрия и климат-поле.
- История модели — ровно 672 ч (28 суток); горизонт — 168 ч. Прогноз не видит того, чего нет
  в истории одной точки (приходящие фронты), поэтому на дальних лидах он стремится к
  климатологии.
- Обучение только на реанализе. Перенос на реальные приборы измеряется внешним тестом,
  а не предполагается.
- Координаты и высота каждого обучающего окна при обучении случайно сдвигаются (в профиле
  по умолчанию до ±0,4° по широте и долготе, высота — с σ = 50 м), в том числе в окнах без
  истории, на которых учится климат-поле. Поле поэтому сглажено на масштабе в десятки
  километров: в горах и на побережьях климатическое среднее и разброс точки размыты.

## Как это работает

Прогноз раскладывается на климатический якорь и аномалию. Климат-поле по координатам даёт
среднее и масштаб разброса для каждого часа горизонта. Аномалия собирается из затухающих
мод памяти, которые читаются из истории причинным свёрточным энкодером; вклад мод
взвешен массой свидетельств, поэтому без истории аномалия равна нулю и прогноз равен
климатологии. Погодная часть аномалии измеряется в единицах разброса поля — того же, что
нормирует историю. Устойчивое смещение станции несёт отдельная квазипостоянная мода, и
измеряется оно в градусах: постоянное смещение прибора на выходе одинаково на всех часах
суток. Паспорт станции по суточным сводкам истории подстраивает под точку ширину интервала
и постоянные времени мод; климатическое среднее и перевод аномалии в градусы от паспорта
не зависят. Квантили строятся вокруг медианы монотонными смещениями. На устройстве новый
час стоит один шаг энкодера и мод и не зависит от длины истории; при выпуске
пересчитывается край окна. Описание компонентов, бейзлайнов и источники всех методов —
[`MODELS.md`](MODELS.md).

## Установка

Нужны Python 3.11+, [uv](https://docs.astral.sh/uv/) и, для рантайма, Rust 1.88+.

```bash
git clone https://github.com/feyra-labs/tempcast.git
cd tempcast
uv sync --group dev          # PyTorch берётся из индекса CUDA 12.8, работает и на CPU
uv run pytest -q             # тесты на синтетике, данные не нужны
cargo test --release --manifest-path runtime-rs/Cargo.toml
```

Все команды ниже запускаются из корня репозитория через `uv run`, у каждой есть `--help`.

## Данные

Данные в репозиторий не входят и собираются скриптами. Нужна карта зон Кёппена — Гейгера
с кодами 1..30, например `Beck_KG_V1_present_0p0083.tif` из Beck et al. (2018).

```bash
# обучающий набор: точки на суше, ERA5 из архивного API Open-Meteo, станции и манифест
uv run python scripts/make_points.py --koppen Beck_KG_V1_present_0p0083.tif --out data/points.csv
uv run python scripts/fetch_era5.py --points data/points.csv --out data     # 2016–2025, докачка
uv run python scripts/make_era5.py --data data
uv run python scripts/make_splits.py --manifest data/manifest.csv          # роли станций
uv run python scripts/build_cache.py --manifest data/manifest.csv --jobs 8 # QC и климатология

# внешний тест: наблюдения GHCNh, только почасовые станции
uv run python scripts/fetch_ghcnh.py --out data/ghcnh/raw --years 2016-2025 \
    --bbox 35 60 -10 40 --max-stations 300 --jobs 8
uv run python scripts/make_ghcnh.py --raw data/ghcnh/raw --out data/ghcnh \
    --koppen Beck_KG_V1_present_0p0083.tif --dem open-meteo
uv run python scripts/build_cache.py --manifest data/ghcnh/manifest.csv
```

Для проверки конвейера без скачивания: `uv run python scripts/make_synth.py`, затем
`make_splits.py` и `build_cache.py` как выше.

| путь | что это |
|---|---|
| `data/points.csv` | `id, lat, lon, koppen` — выбранные точки |
| `data/era5/<id>.json.gz` | ответ API по точке вместе с параметрами запроса |
| `data/fetch_meta.json` | эндпоинт, модель, переменные, период, коммит скачивания |
| `data/stations/<id>.npz` | почасовые `T`, `P`, `RH`, маска наличия `valid`, начало ряда `t0_utc_h` |
| `data/manifest.csv` | `id, lat, lon, elev, koppen, cell_lat, cell_lon, split` |
| `data/splits_report.json` | число станций по ролям, страты, раскладка времени |
| `data/cache/<ключ>/` | кэш после QC, `qc_report.csv`, `meta.json` |
| `data/ghcnh/manifest.csv` | станции внешнего теста, роль `external_test` |
| `data/ghcnh/selection_report.csv` | причина исключения каждой станции GHCNh |

Роли станций: около 15 % — тест на новых станциях (`unseen_test`), 10 % оставшихся —
валидация (`unseen_val`), остальные — обучение (`train`), внутри страт «зона Кёппена ×
широтный пояс». Ряд каждой станции делится на обучение, зазор 840 ч, год чередующихся
блоков валидации и калибровки, зазор 840 ч и тестовый год.

Лицензии данных: Open-Meteo — CC BY 4.0, бесплатный API только для некоммерческого
использования; ERA5 — Copernicus Climate Change Service; GHCNh — NOAA NCEI. Полные ссылки —
в [`MODELS.md`](MODELS.md).

## Обучение

```bash
# этап A (поле при нулевой истории) и этап B (полный куррикулум) одной командой
uv run python scripts/train.py --arch mayak --manifest data/manifest.csv --accelerator gpu
# нейробейзлайны по тому же протоколу
uv run python scripts/train_neurobaselines.py --manifest data/manifest.csv --accelerator gpu
```

Чекпойнт — `runs/<arch>/stageB/best.ckpt`, журнал — `runs/<arch>/protocol.json`.

Все модели обучаются в fp32 без TF32 — в той же точности, в которой их оценивают,
калибруют и экспортируют; чекпойнты другой точности стенд оценки не принимает. Обучающие
окна искажаются аугментациями, которые имитируют реальный прибор (`conf/augment/`, описание —
в [`MODELS.md`](MODELS.md), раздел «Обучение»). Дрейф прибора в обучении и в проверке
робастности — один и тот же прибор, заданный скоростью в сутки и возрастом калибровки к
началу истории: в обучении возраст случаен, потому что начало окна с калибровкой датчика не
связано, в проверке робастности он нулевой.

Этапы по отдельности, с решением человека между ними:

```bash
uv run python scripts/train.py --arch mayak --stages A              # кандидаты и отчёт о поле
uv run python scripts/stage_report.py a --run runs/mayak            # пересчёт отчёта
uv run python scripts/train.py --arch mayak --stages B \
    --init-from runs/mayak/stageA/candidates/<шаг>.ckpt --require-gate 1.05
```

Абляции и сиды — через Hydra, каждый прогон в `runs/mayak-<абляция>-s<сид>/`:

```bash
for a in none no_compression; do uv run python scripts/run.py ablation=$a train.seed=0; done
for s in 1 2; do uv run python scripts/run.py train.seed=$s; done
```

## Результаты

Чисел пока нет: таблицы заполняются из JSON в [`results/`](results/README.md) после полного
прогона. Все сравнения — по сырым выходам моделей; конформная поправка — отдельная таблица
для МАЯК. Скилл — снижение MSE относительно климатологии самой станции; «пул» — по всем
парам «окно × лид», «макро» — среднее по станциям; в JSON у каждого числа интервал
бутстрапа по станциям (90 %). Основные таблицы — при полной истории 672 ч. Интервалы
статистических эталонов нормальные, с масштабом остатка климатологии станции на каждом
часе горизонта — тем же, что нормирует функцию потерь всех нейросетей.

Таблицы 1–6 считаются на одном наборе тестовых окон: начала горизонта с шагом 72 ч в
тестовом году станций, затем стратифицированная подвыборка в пределах бюджета набора
(6000 окон). Внутренний тест объединяет обучающие станции (`train`) в их тестовом году и
станции, не виденные при обучении (`unseen_test`); по отдельности роли показывает
таблица 3–4.

Таблицы 1–6 и 11 считает одна команда:

```bash
uv run python scripts/calibrate.py --ckpt runs/mayak/stageB/best.ckpt --out runs/conformal.npy
uv run python -m mayak.evaluate --ckpt runs/mayak/stageB/best.ckpt \
    --gru-ckpt runs/gru/stageB/best.ckpt --dlinear-ckpt runs/dlinear/stageB/best.ckpt \
    --lru-ckpt runs/lru/stageB/best.ckpt --patchtst-ckpt runs/patchtst/stageB/best.ckpt \
    --conformal runs/conformal.npy --external-manifest data/ghcnh/manifest.csv \
    --bootstrap 1000 --results-dir results/evaluate
```

## Рантайм на устройстве

На устройство копируются два артефакта: бинарник `mayak-rt` и каталог экспорта модели.
Python на устройстве не нужен.

**1. Экспорт модели** (на рабочей машине):

```bash
uv run python scripts/export_runtime.py --ckpt runs/mayak/stageB/best.ckpt \
    --conformal runs/conformal.npy --aci --out runtime/model
```

Вариант int8: таблица подгоняется на int8-графах того же экспорта.

```bash
uv run python scripts/export_runtime.py --ckpt runs/mayak/stageB/best.ckpt --int8 --out runtime/model
uv run python scripts/calibrate.py --ckpt runs/mayak/stageB/best.ckpt --precision int8 \
    --model-dir runtime/model --out runs/conformal_int8.npy
uv run python scripts/export_runtime.py --ckpt runs/mayak/stageB/best.ckpt --int8 \
    --conformal runs/conformal_int8.npy --aci --out runtime/model
```

**2. Сборка бинарника.** Для Linux x86_64 и aarch64 ONNX Runtime 1.28 скачивается при сборке
и вшивается в бинарник. Это любая 64-битная ОС, в том числе Raspberry Pi 3/4/5 с 64-битной
Raspberry Pi OS.

```bash
# прямо на устройстве
curl --proto '=https' -sSf https://sh.rustup.rs | sh
cargo build --release --manifest-path runtime-rs/Cargo.toml
# бинарник: runtime-rs/target/release/mayak-rt

# или кросс-сборкой с x86_64 Linux
rustup target add aarch64-unknown-linux-gnu
sudo apt install gcc-aarch64-linux-gnu g++-aarch64-linux-gnu
CARGO_TARGET_AARCH64_UNKNOWN_LINUX_GNU_LINKER=aarch64-linux-gnu-gcc \
    cargo build --release --target aarch64-unknown-linux-gnu --manifest-path runtime-rs/Cargo.toml
# бинарник: runtime-rs/target/aarch64-unknown-linux-gnu/release/mayak-rt
```

Для других платформ (например, 32-битной armv7) готовой сборки ONNX Runtime нет. Нужна своя
`libonnxruntime.so` версии 1.28 или новее, собранная по
[инструкции ONNX Runtime](https://onnxruntime.ai/docs/build/inferencing.html), и сборка с
загрузкой библиотеки при старте:

```bash
cargo build --release --no-default-features --features ort-dynamic --manifest-path runtime-rs/Cargo.toml
export ORT_DYLIB_PATH=/opt/mayak/lib/libonnxruntime.so     # на устройстве, перед запуском
```

**3. Установка.**

```bash
ssh pi@device 'sudo mkdir -p /opt/mayak /var/lib/mayak && sudo chown $USER /opt/mayak /var/lib/mayak'
scp runtime-rs/target/aarch64-unknown-linux-gnu/release/mayak-rt pi@device:/opt/mayak/
scp -r runtime/model pi@device:/opt/mayak/model
ssh pi@device /opt/mayak/mayak-rt info --model /opt/mayak/model   # размеры, бины калибровки
```

**4. Запуск.** `mayak-rt run` читает команды со stdin по одной на строку и отвечает строкой
JSON: `obs <секунды UTC> <T> <P> <RH>` (`-` — нет данных), `forecast`, `status`. Для int8-экспорта
добавьте `--int8`. Координаты и высота точки над уровнем моря (`--lat`, `--lon`, `--elev`)
обязательны, без любого из них рантайм не запускается: по ним считаются климат-поле и
проверка давления в QC. Высоту нужно указать сразу: если позже исправить её больше чем на
порог манифеста (`mayak-rt info`, по умолчанию 100 м), рантайм сочтёт это переносом прибора
и начнёт с пустой истории.

```bash
printf 'obs 1767225600 11 1012.4 81\nforecast\n' | /opt/mayak/mayak-rt run \
    --model /opt/mayak/model --lat 52.37 --lon 4.90 --elev -2 --state-dir /var/lib/mayak --aci
```

После каждого наблюдения состояние пишется в `--state-dir`; после перезапуска рантайм
продолжает с того же часа, простой заполняется пустыми часами. Если точка сменилась больше
порогов манифеста, прибор считается перенесённым и стартует с пустой историей. Для
постоянной работы программа датчика пишет строки в именованный канал, а рантайм работает
службой:

```ini
# /etc/systemd/system/mayak-rt.service
[Unit]
Description=MAYAK forecast runtime

[Service]
User=pi
RuntimeDirectory=mayak
ExecStartPre=/usr/bin/mkfifo -m 600 /run/mayak/in
ExecStart=/bin/sh -c 'exec /opt/mayak/mayak-rt run --model /opt/mayak/model --lat 52.37 \
    --lon 4.90 --elev -2 --state-dir /var/lib/mayak --aci 0<>/run/mayak/in >>/var/lib/mayak/out.jsonl'
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now mayak-rt
echo "obs $(date -u +%s -d "$(date -u +%Y-%m-%dT%H:00:00)") 11 1012.4 81" > /run/mayak/in
echo forecast > /run/mayak/in && tail -n 1 /var/lib/mayak/out.jsonl
```

Прибор рассчитан на ежечасный выпуск: `forecast` можно отправлять после каждого `obs`.
Интервалы прогноза проходят две поправки. Конформная таблица из экспорта применяется по
длине истории — числу часов после холодного старта, не больше 672. С `--aci` интервал
дополнительно растягивается множителем `e^θ`, своим для каждого бина лидов (1–6, 7–24, 25–72,
73–168 ч). Для сверки с фактом бин записывается не каждым выпуском, а выпусками в часы,
согласованные с шириной бина, и тогда целиком, всеми лидами. Поэтому каждый час
сверяется ровно с одним прогнозом из каждого бина, а при ежечасном выпуске θ бина
подстраивается по всем его лидам поровну, а не только по самому короткому (правило записи
приведено в разделе «Формулы» `MODELS.md`). Калибровка рассчитана на ежечасный выпуск: если
отправлять `forecast` реже, бин получает обратную связь только с выпусков, попавших на
его часы. У бинов по умолчанию первый лид нечётный, а ширина чётная, поэтому выпуски в
чётные часы UTC не калибруются вовсе, а при выпуске раз в 6 ч обратную связь дают только
выпуски в 5, 11, 17 и 23 ч UTC.
Записи прогнозов для этой сверки живут только в памяти и после перезапуска пусты; θ
хранятся в состоянии.

Ответ `forecast` содержит `theta` — список θ по бинам лидов. Поля `status`:

| поле | что это |
|---|---|
| `filled`, `history_hours` | часов в окне после холодного старта; длина истории, по которой выбирается строка конформной таблицы (`filled`, не больше 672) |
| `theta`, `aci_lead_bins` | θ по бинам лидов и сами бины, ч |
| `aci_updates`, `aci_misses` | обратных связей и промахов по бинам лидов с последнего сброса |
| `conformal` | применяется ли конформная таблица |
| `state_bytes` | размер состояния на диске: 3236 Б при окне 672 ч |
| `memory_bytes` | кольца, буфер энкодера, климатология и при `--aci` записи калибровки (13 440 Б) |
| `site`, `loaded_site`, `site_change` | точка прибора, точка загруженного состояния и исход сравнения |
| `idle_hours`, `fallbacks`, `last_unix_hour`, `rss_bytes`, `peak_rss_bytes` | простой, откаты к климатологии, последний час, память процесса |

Состояние версии 5 хранит θ по бинам лидов; состояние версии 4 с одним θ читается, и его θ
переносится во все бины. Манифест экспорта — формата 5, со списками бинов лидов и длины
истории; `mayak-rt info` их показывает. Экспорт формата 4 рантаймы не читают — модель нужно
экспортировать заново.

Хост на Python с тем же протоколом и форматом состояния, для проверки на рабочей машине:

```bash
uv run python -m mayak.runtime.run_inference --model runtime/model --lat 52.37 --lon 4.90 \
    --elev -2
```
